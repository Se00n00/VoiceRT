# 04 — Sessions

Identity, who owns the window, and what survives a restart.

## 4.1 Identity

Ids look like opencode's: `ses_` + 26 base62 characters.

| Side | Function | Rule |
|---|---|---|
| TUI | `newSessionId()` — `src/tui/src/session.ts:9-14` | `randomBytes(26)`, `62^26` space |
| TUI | `normalizeSessionId()` — `src/tui/src/session.ts:17-23` | accepts bare or prefixed; body must match `^[0-9A-Za-z]{6,64}$`; returns null otherwise |
| Python | `_safe_sid()` — `src/agent/memory.py:232-240` | filename-safe, else hashed |

The TUI rejects `../../etc/passwd` because the body regex allows only
alphanumerics — there is no dot and no slash to exploit. The Python side is
defended separately, because there the id *is* a filename.

An id is generated by the client and passed to the bridge on every turn. The
server never mints one for a WS connection.

## 4.2 Who owns the window

This is the part that keeps getting re-litigated, so:

**`VoiceAgent` holds conversation windows in memory only.** Persisting them is
*application* work. The agent exposes the pair and no opinion:

| Call | When | Signature |
|---|---|---|
| `import_session(sid, data)` | app start | `src/main.py:445-465` |
| `export_session(sid)` | after each turn | `src/main.py:443-444` |

```python
def export_session(self, session_id: str) -> list:
    return self.history(session_id)
```

`import_session` converts `{"role","content"}` dicts into LangChain messages
and appends them one by one. **Both never raise** — the whole body is wrapped
in a bare `except Exception: pass` (`src/main.py:464-465`), so a corrupt
restore file degrades to an empty session instead of a dead process.

Reference implementation: `examples/say_hii.py`, which does the
load-on-start / write-back-per-turn dance itself.

## 4.3 The two window stores

Both live in `src/agent/memory.py` and share a surface; the agent picks one.

```
LangChainSessionMemory   RAM only, 20 turns / 30 min / 1000 sessions
JsonSessionMemory        one JSON file per session, atomic writes, TTL sweep on load
```

Full eviction semantics are in [03-memory.md](03-memory.md#32-l1--the-window).
The short version: TTL sweep, LRU at `max_sessions`, prune to
`2 × max_turns`, and an optional token cap.

Sessions never hold GPU resources — only text — which is why stored sessions
may vastly outnumber in-flight turns. That is deliberate and it is why the
scheduler and the session store are orthogonal concerns.

## 4.4 Serialization per session

`_run_locked` (`src/main.py:772-811`) takes a lock keyed by `session_id`.
Contenders are appended to `_pending` (`src/main.py:788-791`) and drained when
the lock releases (`src/main.py:804-811`) — the TUI shows these as
`term/queued` (`src/main.py:789`).

A queue, not a drop, and not a second lock per session: two turns interleaving
into one window is the bug this prevents.

## 4.5 TUI-side persistence

`src/tui/src/session.ts` owns three things:

1. `newSessionId()` / `normalizeSessionId()` — identity
2. `sessionName(firstUtterance)` — an **offline** fallback title derived from
   the first user message by dropping stop words and title-casing the first
   two (`session.ts:26+`). It exists so a session is never blank, not to replace
   the model's title.
3. The resume flag: `voicert -s <id>`, printed on the epilogue card.

Sessions written to `.voicert/<session_id>.json` are the app's job. The agent's
`export_session`/`import_session` pair is the only supported way to do it.

## 4.6 Titles

Generated by the front brain, two words, 12 tokens max
([01-agent.md](01-agent.md#17-titles)). Stored via `set_title`/`get_title`
(`src/agent/memory.py:199-219`).

`_maybe_title` (`bridge.py:187`) fires it in the background off the WS handler
so a 0.6B generation never delays the reply the user is already reading.

The id to resume is printed on the exit card:

```
  Session   Friendly greeting
  Continue  voicert -s ses_xWGk1a2b
  Version   v0.0.1
```

## 4.7 Resuming

```
voicert -s ses_xWGk1a2b
```

The TUI normalizes the id, asks the bridge for the window, and restores it. If
the bridge has no record (fresh process), the app is responsible for loading its
own persisted JSON via `import_session`.

## 4.8 Known gaps

- Stale titles survive session eviction — `_titles` is not swept with the LRU.
- `_maybe_title` on the `/deep` path was never audited, unlike the primary
  turn.
